# Lessons (portfolio)

## Contenu des projets (Projects.tsx)
- La `longDescription` d'un projet est un **pitch produit** dans le ton des projets existants (« X est une plateforme/application qui... », bénéfices utilisateur, fonctionnalités, « Intégration Stripe pour la monétisation... », phrase de conclusion). **Pas** un compte rendu technique de mission (RLS, proxy serveur, région UE, RGPD...). Relire 2-3 descriptions existantes avant d'en rédiger une.
- Features : orientées utilisateur, pas d'infra/conformité.
- Pas de tiret cadratin (—) dans les textes.

## Vérification
- Ne pas lancer d'agent navigateur pour vérifier le rendu si l'utilisateur dit qu'il vérifie lui-même : s'arrêter au build.
